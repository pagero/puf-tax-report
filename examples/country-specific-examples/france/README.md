# PUF Tax Report — France Examples

Example files for French payment reporting (Flux 10, sub-streams 10.2 and 10.4).

## Example Files

| File | Classification | Type | Description |
|------|---------------|------|-------------|
| `PUF_FR_payment_income_invoices_and_transactions.xml` | INCOME | — | Payment reporting for sales. Covers B2B invoice payments with mixed VAT rates (20% + 5.5%) and B2C receipt transaction payments with aggregated daily POS data (20%, 10%, 5.5%). |
| `PUF_FR_payment_rectification.xml` | INCOME | RECTIFICATION | Rectification of a previously reported payment period. Demonstrates `Type` = RECTIFICATION with `ReportPeriod`. |
| `PUF_FR_payment_add.xml` | INCOME | ADD | Supplementary report for an already reported period (January 2026). Adds one missing B2B invoice payment; references the original report via `cac:DocumentReference`. |
| `PUF_FR_payment_edit.xml` | INCOME | EDIT | Correction of one entry (invoice `FAC-2025-00901`, 5000.00 → 4750.00) of the report in `PUF_FR_payment_income_invoices_and_transactions.xml`; references it via `cac:DocumentReference`. Other entries are not repeated. |
| `PUF_FR_payment_sending_business_unit.xml` | INCOME | — | Original payment report that sets `SendingBusinessUnit` (free-text source system/department label, searchable in the Pagero UI) together with `IssuerAssignedID` and its own Tax report id (`cbc:ID`). |
| `PUF_FR_payment_receipt_transactions.xml` | INCOME | — | B2C/POS payments (sub-stream 10.4) referenced by payment date only: `PaymentDataType` = `RECEIPTTRANSACTION`, no invoice id or date, one `Payment` per day split per VAT rate. |
| `PUF_FR_UC43_international_b2b_payment.xml` | INCOME | — | UC43: Payment reporting for international B2B services (Flux 10.2). Demonstrates payment received on invoices for services performed in France for EU clients. Includes full and partial payment examples. |

## Key Concepts

- **ClassificationIdentifier**: `INCOME` for sales/revenue reporting, `EXPENSE` for purchase reporting. Only `INCOME` is relevant in France.
- **PaymentDataType**: `INVOICE` for B2B invoice payments (sub-stream 10.2), `RECEIPTTRANSACTION` for B2C/POS payments (sub-stream 10.4).
- **Type**: `ADD`, `EDIT`, or `REPLACE_PERIOD` — indicates the nature of the submission. `ADD` adds supplementary data, `EDIT` corrects individual entries, `REPLACE_PERIOD` fully replaces a previously submitted report for the period. (During a transition period `RECTIFICATION` may still be used and should later be changed to `REPLACE_PERIOD`; the transform also accepts the legacy aliases `ADDITIONAL`/`CO` and `CORRECTIVE`/`MO`.)
- **ReportPeriod**: The reporting period (`StartDate` / `EndDate`) the payment data covers.
- **Currency**: Must be `EUR` for French payment reporting.
- **IssuerParty**: The declaring party, identified by SIREN (`schemeID="0002"`).

## Report Identifiers

| Field | Path | Purpose |
|-------|------|---------|
| Tax report id | `cbc:ID` | Identifies this specific report. Set it on every original submission, because an EDIT can only reference a report that has one. |
| Issuer assigned report id (TT-1) | `IssuerAssignedID` | Free-text, human-readable label. Not used to match reports. |
| Sending business unit | `SendingBusinessUnit` | Free-text label for the source system or department. No effect on reporting; stored with the report and searchable in the Pagero UI. |
| Aggregated report id | — | Generated by Pagero for the Approved aggregated report. Never set in an original submission. |

## Correction Scenarios

All correction types set `Type` and point to an earlier report with `cac:DocumentReference/cbc:ID`. What the reference must contain depends on the type:

| Scenario | `Type` | `cac:DocumentReference/cbc:ID` | Payments to include | Example |
|----------|--------|-------------------------------|---------------------|---------|
| Add a payment missing from the original submission | `ADD` | Aggregated report id of the Approved report being added to | Only the missing payment(s) | `PUF_FR_payment_add.xml` |
| Correct one specific document already reported | `EDIT` | Tax report id (`cbc:ID`) of the previously sent report containing the entry, e.g. `PAY-2026-001`. Not an aggregated id | Only the corrected entry, with the same invoice reference and paid date as the original | `PUF_FR_payment_edit.xml` |
| Replace the whole period | `REPLACE_PERIOD` | Aggregated report id of the Approved report being replaced | The complete corrected data for the period | `PUF_FR_payment_rectification.xml` |

Notes:

- `ReportPeriod` must match the period of the report being added to, corrected or replaced.
- `IssuerParty` must be the same as in the original report.
- Report ids are unique per submission: a correcting report never reuses the id of the report it refers to.
- `PUF_FR_payment_edit.xml` corrects invoice `FAC-2025-00901` of the report `PAY-2026-001` in `PUF_FR_payment_income_invoices_and_transactions.xml`. `PUF_FR_payment_add.xml` supplements the same January 2026 period.
- `PUF_FR_payment_receipt_transactions.xml` shows payments without an invoice reference: each `Payment` is identified by its `PaidDate` only. The payment report carries no transaction category code (TLB1/TPS1/TNT1/TMA1); that code belongs to the transaction report of the sales (Flux 10.3).
- `PUF_FR_payment_sending_business_unit.xml` is an original report (no `Type`) showing the three identifier fields above.
